Sistema de Gestión de SolicitudesRequest Management System

Una universidad manejaba las solicitudes de servicio de sus estudiantes en papel y hojas de cálculo dispersas. No había trazabilidad: nadie sabía en qué estado estaba una solicitud, quién la había aprobado, ni cómo generar el reporte mensual sin transcribir a mano. A university was handling student service requests on paper and scattered spreadsheets. There was no traceability: nobody knew a request's status, who approved it, or how to produce the monthly report without transcribing by hand.

El problemaThe problem

Una solicitud pasa por cuatro perfiles antes de quedar cumplida, y en papel nada impedía que se firmara en desorden. El estado real del trámite vivía en la memoria de quien tuviera la carpeta: el estudiante no podía saber dónde estaba su solicitud sin ir a preguntar de escritorio en escritorio, y el reporte mensual se armaba transcribiendo a mano.A request passes through four profiles before it is fulfilled, and on paper nothing stopped it from being signed out of order. The real status lived in the memory of whoever held the folder: a student could not find out where their request stood without asking desk by desk, and the monthly report was assembled by transcribing it by hand.

Cómo lo decidíHow I decided

El estado no es un texto que alguien escribe: son siete valores cerrados, y cada operación exige el estado previo correcto antes de tocar nada. Un administrador solo puede aprobar lo que ya está esperando su revisión; si la solicitud llega en cualquier otro estado, el servidor rechaza la operación en lugar de confiar en que la pantalla escondió el botón. Un campo de estatus libre se programa en una tarde y admite lo imposible, como una solicitud aprobada que nadie revisó. El historial va aparte, como eventos que solo se agregan: cada cambio escribe estado anterior, estado nuevo, responsable y fecha, y no existe ninguna ruta en el código que edite esa tabla. Una trazabilidad que se puede corregir a mano no es trazabilidad.Status is not free text someone types: it is seven closed values, and every operation demands the correct prior state before touching anything. An administrator can only approve what is already awaiting their review; if the request arrives in any other state, the server rejects the operation instead of trusting that the screen hid the button. A free-text status field takes an afternoon to build and admits the impossible, like a request approved by someone who never reviewed it. History lives apart, as events that are only ever appended: each change writes previous state, new state, who did it and when, and no code path edits that table. Traceability you can correct by hand is not traceability.

ResultadoResult

El trámite dejó el papel y hoy vive en una aplicación web: los cuatro perfiles entran con su propia cuenta y trabajan sobre la misma solicitud, no sobre copias. Eso es lo que cerró el problema, porque ya no hay carpeta que perseguir ni controles paralelos que conciliar: el estado del trámite es uno solo y está siempre en el mismo lugar. Cualquiera puede reconstruir quién hizo qué y cuándo consultando el historial, y el reporte mensual que antes costaba días de transcripción ahora sale con un clic. Está en producción.The process left paper behind and now lives in a web application: the four profiles sign in with their own account and work on the same request, never on copies. That is what closed the problem, because there is no folder to chase and no parallel records to reconcile: the status of a request is single and always in the same place. Anyone can reconstruct who did what and when from the history, and the monthly report that used to cost days of transcription now comes out with one click. It is in production.

Lo que haceWhat it does

  • Ordena el trámite. Cuatro perfiles participan en el proceso y cada solicitud avanza por pasos claros. En todo momento se sabe dónde está y quién sigue.It organizes the process. Four profiles take part, and every request moves through clear steps. At any moment you know where it is and whose turn it is.
  • Deja rastro. Cada aprobación queda registrada con su responsable y su fecha. Ya nadie tiene que reconstruir a mano lo que pasó.It leaves a trail. Every approval is recorded with who did it and when. Nobody has to piece together what happened.
  • Genera el reporte solo. Lo que antes eran días transcribiendo a una hoja de cálculo ahora es un clic.It builds the report itself. What used to be days of transcribing into a spreadsheet is now one click.
  • Responde las dudas repetidas. Un asistente resuelve las preguntas frecuentes del proceso y le quita carga al personal.It answers the repeat questions. An assistant handles frequent questions about the process and takes load off the staff.
  • Avisa a quien toca. Cada cambio dispara un correo, así nadie tiene que estar preguntando.It notifies the right person. Each change triggers an email, so nobody has to chase updates.

Cómo lo penséHow I approached it

  • La seguridad vive en el servidor. Cada operación se valida ahí, no en la pantalla, porque ocultar un botón no es seguridad. Hay una prueba automatizada dedicada a comprobar que un usuario no pueda leer lo que pertenece a otro.Security lives on the server. Every operation is validated there, not on screen, because hiding a button is not security. There is a dedicated automated test asserting that one user cannot read what belongs to another.
  • Ninguna contraseña en texto plano, ni en el repositorio ni en el servidor, y límite de intentos en el inicio de sesión.No password in plain text, not in the repo nor on the server, plus attempt limits on sign-in.
  • Los scripts de base de datos se pueden correr dos veces sin romper nada. Lo aprendí arreglando una instalación limpia que fallaba.Database scripts can run twice without breaking anything. I learned that fixing a clean install that failed.
  • Los índices están pensados, no adivinados. La pantalla más usada filtra por estado y ordena por fecha, así que el índice es compuesto y en ese orden. Las llaves foráneas ya venían indexadas por el motor: ese trabajo no había que repetirlo.Indexes are deliberate, not guessed. The most-used screen filters by state and sorts by date, so the index is composite and in that order. Foreign keys were already indexed by the engine: that work did not need repeating.
  • Se entrega documentado. Manual técnico, manual de usuario y guía de instalación, porque un sistema que solo yo puedo levantar no está terminado.It ships documented. Technical manual, user manual and install guide, because a system only I can deploy is not finished.

Devengo: adelanto de salario devengadoearned wage access

Un trabajador que ya generó su salario no debería esperar a la quincena para acceder a él, ni recurrir a préstamos con intereses abusivos. El reto era construir la plataforma que permite ese adelanto, con sus reglas de negocio, controles de riesgo y liquidación, en el tiempo de un hackathon. A worker who has already earned their wages shouldn't wait for payday to access them, nor turn to predatory loans. The challenge: build the platform enabling that advance, with its business rules, risk controls and settlement, within a hackathon's timeframe.

El problemaThe problem

En un adelanto de salario, lo disponible no es un dato: es un número en movimiento. Sube cada día que el trabajador acumula y baja con cada retiro que ya hizo. Entre que el trabajador pide y que Recursos Humanos aprueba pasan minutos u horas, y en ese hueco la cifra pudo cambiar. En un hackathon nadie lo nota porque la demo dura dos minutos; con dinero real es la diferencia entre pagar lo que existe y pagar lo que ya no existe.In an earned wage advance, what's available is not a stored value: it is a moving number. It rises with every day the worker accrues and falls with every withdrawal already taken. Minutes or hours pass between the worker asking and HR approving, and in that gap the figure may have changed. In a hackathon nobody notices because the demo lasts two minutes; with real money it is the difference between paying what exists and paying what no longer does.

Cómo lo decidíHow I decided

La regla que decide cuánto puede retirar alguien se implementa una sola vez y las tres superficies la consumen. Copiar la fórmula en cada cliente avanza más rápido durante el fin de semana, y el costo llega después: una copia se desincroniza y el usuario ve un número distinto al que se le deposita. La segunda decisión fue no confiar en el monto que venía guardado con la solicitud: al aprobar, el servidor vuelve a calcular el disponible y rechaza la operación si ya no alcanza, aunque sí alcanzara cuando el trabajador la pidió. Es más código y una ruta de error más que explicar, pero la alternativa es autorizar contra una cifra vencida. Para la identidad usé Keycloak en lugar de escribir la autenticación yo: bajo presión de tiempo, la autenticación propia es justo donde se abren los huecos, y no es el lugar para ahorrar horas.The rule that decides how much someone may withdraw is implemented once and consumed by all three surfaces. Copying the formula into each client moves faster over the weekend, and the cost arrives later: one copy drifts and the user sees a different number than the one deposited. The second decision was not to trust the amount stored with the request: on approval, the server recomputes what is available and rejects the operation if it no longer covers it, even if it did when the worker asked. That is more code and one more error path to explain, but the alternative is authorizing against a stale figure. For identity I used Keycloak instead of writing auth myself: under time pressure, homemade auth is exactly where the holes open, and it is not the place to save hours.

ResultadoResult

Al cierre del hackathon corrían el portal web, la app móvil y los contratos en la red de pruebas de Stellar, los tres leyendo la misma fuente para las cifras. El trabajador pedía su adelanto, Recursos Humanos lo aprobaba o lo rechazaba dejando el motivo por escrito, y el movimiento quedaba asentado en la bóveda con su comisión y su monto neto. Cerrar la quincena recalcula el ciclo y deja sin efecto lo que quedó pendiente, para que ninguna solicitud sobreviva al periodo que la originó. Es un prototipo de fin de semana y lo trato como tal: probó que la idea se sostiene de extremo a extremo, no que esté lista para mover dinero de verdad.By the end of the hackathon the web portal, the mobile app and the contracts on Stellar's testnet were all running, all three reading the same source for the figures. The worker requested an advance, HR approved or rejected it leaving the reason on record, and the movement was posted to the vault with its fee and net amount. Closing the pay period recomputes the cycle and voids whatever was still pending, so no request outlives the period that created it. It is a weekend prototype and I treat it as one: it proved the idea holds end to end, not that it is ready to move real money.

  • Panel administrativo para dirección y recursos humanos: tableros de control, gestión de plantilla, configuración de políticas de retiro y aprobación de solicitudes.Admin panel for leadership and HR: dashboards, headcount management, withdrawal policy configuration and request approval.

Sistema de gestión de recursosResource Management System

El centro de desarrollo presta equipo caro a estudiantes y docentes: proyectores, kits de robótica, laptops, cámaras. El control vivía en libretas y hojas de cálculo, así que nadie sabía con certeza quién tenía qué ni desde cuándo, y cada semestre se perdía material. El sistema pone ese inventario en un solo lugar, con reservas fechadas, aprobación explícita y aviso por correo en cada paso del préstamo. The development center lends expensive gear to students and faculty: projectors, robotics kits, laptops, cameras. Tracking lived in notebooks and spreadsheets, so nobody knew for sure who had what or since when, and equipment went missing every semester. The system puts that inventory in one place, with dated reservations, explicit approval and an email notice at every step of the loan.

El problemaThe problem

Prestar equipo caro no es un sí o un no: una reserva nace pendiente, alguien la aprueba o la rechaza, el equipo sale y algún día tiene que regresar. En libretas ese ciclo se rompía justo en el último paso, que es el que importa: quedaba anotado quién pidió, casi nunca quién devolvió. Y no todos pueden lo mismo. Un estudiante solicita, el personal opera y el administrador decide, y esa diferencia no podía depender de qué botones ve cada quien en la pantalla.Lending expensive equipment is not a yes or a no: a reservation is born pending, someone approves or rejects it, the gear goes out, and one day it has to come back. In notebooks that cycle broke precisely at the last step, the one that matters: who asked was written down, who returned it almost never was. And not everyone can do the same things. A student requests, staff operate and the administrator decides, and that difference could not depend on which buttons each person sees on screen.

Cómo lo decidíHow I decided

Modelé la reserva como un conjunto cerrado de estados y le di a «devuelta» un estado propio, en vez de resolverlo con una casilla de «ya regresó». Cancelada y devuelta se parecen desde la interfaz y no son lo mismo: una cierra el préstamo porque nunca ocurrió y la otra porque terminó bien, y mezclarlas vuelve imposible responder qué equipo está afuera hoy. El control de acceso lo puse en el servidor, declarando en cada operación qué rol puede ejecutarla; en React también protegí las rutas, pero eso es comodidad para el usuario, no seguridad, porque la pantalla oculta y el servidor decide. Y para recuperar contraseña mando un código de un solo uso que caduca, en lugar de enviar la contraseña por correo: una contraseña que viaja por correo se queda ahí para siempre.I modelled the reservation as a closed set of states and gave "returned" a state of its own, instead of solving it with a "came back" checkbox. Cancelled and returned look alike from the interface and are not the same: one closes the loan because it never happened, the other because it ended well, and merging them makes it impossible to answer what equipment is out today. I put access control on the server, declaring on each operation which role may run it; in React I also guarded the routes, but that is user convenience, not security, because the screen hides and the server decides. And for password recovery I send a single-use code that expires, rather than emailing the password: a password that travels by email stays there forever.

ResultadoResult

Quedó un sistema completo, construido de punta a punta: la API en Spring Boot con su base de datos y la web en React que la consume. Los tres perfiles entran con su propia cuenta, el inventario de espacios y equipos vive en un solo lugar, y cada préstamo tiene fecha, responsable y estado, así que saber qué hay afuera es una consulta y no una ronda de preguntas.What came out was a complete system, built end to end: the Spring Boot API with its database and the React web app that consumes it. The three profiles sign in with their own account, the inventory of spaces and equipment lives in one place, and every loan has a date, a responsible person and a state, so knowing what is out is a query and not a round of questions.

Lo que construíWhat I built

  • API REST en Spring Boot con Spring Security y JWT. Sesión sin estado: cada petición se valida sola, sin memoria del servidor sobre quién entró antes.REST API in Spring Boot with Spring Security and JWT. Stateless sessions: every request validates on its own, with no server memory of who signed in before.
  • Autorización por rol en cada operación del servidor (administrador, personal, estudiante), no solo rutas escondidas en el cliente.Role authorization on every server operation (administrator, staff, student), not just routes hidden in the client.
  • Recuperación de contraseña por código de un solo uso enviado al correo, con caducidad y marca de usado, para que un código filtrado no sirva dos veces.Password recovery by single-use code sent to email, with expiry and a used flag, so a leaked code cannot work twice.
  • Inventario de espacios y equipos con historial por recurso, para poder reconstruir por dónde pasó cada cosa y no solo dónde está ahora.Inventory of spaces and equipment with per-resource history, so you can reconstruct where each item has been and not only where it is now.
  • Front en React con componentes comunes (botones, tarjetas, insignias de estado) y manejo de errores centralizado, para que la interfaz no se contradiga a sí misma pantalla por pantalla.React front end with shared components (buttons, cards, status badges) and centralized error handling, so the interface does not contradict itself screen by screen.
